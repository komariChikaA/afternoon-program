# 资源准备与惊吓播放（v0.6）

任务：[Issue #3](https://github.com/komariChikaA/afternoon-program/issues/3)。共享 `engine/` 保持字节不变，逻辑仅放在 `game/`。

## 资源边界

`game/assets.js` 从全部场景收集背景、角色和动态电视节目，再补入特写背景、电视机壳、三张惊吓图、标题摄影图、工具图标与 favicon。当前去重后共 **45 张图片、3 种惊吓音效**。SVG 中的摄影内容已内嵌，不依赖远端地址；音乐、环境音及其他普通音效仍使用原来的播放方式。

四个工作队列并发加载。图片必须完成 `Image.decode()` 并有非零自然尺寸；HTTP 惊吓音必须完成 Web Audio 解码。直接打开 `file://` 时使用完成 `canplaythrough` 的 HTMLAudio。失败资源自动尝试三次，每次有超时；仍失败就保留进度、显示重新载入，绝不当作成功。手动重试只处理未完成项，图片成功重试的 URL 会沿用到场景、标题、存档缩略图和工具图标；音效重试绕过失败缓存。

加载期间覆盖层显示进度，主菜单、舞台、工具栏和选项不可交互；开始、继续、读档、直接跳转及键盘推进都有就绪检查。错误时仍可通过 Tab 聚焦重试按钮。请求完成与解码完成分开判断，不能用 `src` 已设置代替资源就绪。

## 演出顺序

三处惊吓首先再次确认预备图片解码，复用保存的原始 Image 对象，在透明且无动画的状态插入舞台，等待两次 RAF，然后进行原来的短黑场和突发画面。声音及完整 270ms / 540ms 演出计时从 hit 阶段开始。HTTP 播放复用预解码 AudioBuffer，触发时不新下载图片或音效。浏览器用户手势解锁声音后播放；静音和减少动态设置仍有效。

解码等待、黑场和惊吓期间阻止手动、Ctrl、已读快进与 Auto 推进。页面隐藏时暂停动画与演出时间，回到页面再完成；标题、节点跳转及菜单通过取消 token 清除等待中的异步演出。菜单关闭后，尚未完成的当前惊吓可重播。`vn:scare-hit` 事件用于回归观察，此时检查真实图片尺寸、对象身份和可见 opacity。

存档只在演出完成后写入 `playedScares`。黑场期间保存再继续，会重播尚未完成的惊吓。原 version 1 存档仍可读取，没有这个字段的惊吓节点会重播一次，避免旧存档漏掉画面。

## 验证

`npm run test:preload` 对冷缓存、延迟图片、有效继续存档的加载锁、三处真实可见画面、预备声音、触发时无新请求、延迟再次解码、导航取消、隐藏页面信号、未完成存档、旧存档、惊吓设置、直接文件打开、手机覆盖层进行浏览器验证。另分别注入 404、损坏 JPG、损坏 WAV、普通背景失败、工具图标失败，以及运行时再次解码失败，验证错误与恢复。注入的预期失败单独记录，不混入正常流程错误统计。

本机结果：62项预加载专项断言、452项完整剧情断言（406次操作、395个不同节点）、361项多端断言全部通过。项目验证器通过，共享引擎SHA256保持一致。

证据在 `output/preload/results.json` 与截图；正常完整剧情和八种屏幕尺寸仍分别由 `npm test`、`npm run test:responsive` 检查，CI 三项全部通过后才允许 Pages 部署。隐藏页面检查模拟 visibility API 状态切换；截图可能在短促演出已经淡出时捕获，以 hit 时的解码、可见状态及演出时长断言为准。

预加载不能使损坏或永久不可访问的文件成功显示，遇到这种情况会明确停在错误页；网络恢复后重试继续。技术回归通过后状态为 Qualified，游戏节奏与惊吓观感仍保留玩家验收。
